# HANDOVER — fishing forecast project

**Read this first, then `docs/ARCHITECTURE.md`.** This file is the operational handover: what
exists, what is verified, what is broken, and exactly what to build next. `docs/ARCHITECTURE.md`
is the design document (the *why*); this file is the *where are we and what now*.

Repo root: wherever this repository is checked out (the work was done on Windows with a Git Bash shell:
use forward slashes in paths for the tools there).

---

## 1. Mission

A Home Assistant integration that forecasts **how good the fishing is right now and in the next
48 hours at a specific mark**, plus a self-contained Lovelace card that renders it. It must reason
over weather, water temperature, pressure and fronts, moon/solunar timing, light, tide, river state
and local climatology — and it must explain *why* a score came out the way it did.

Deliverables:
1. `custom_components/fishing/` — HA integration (thin glue).
2. `custom_components/fishing/model/` — the science, **zero dependencies, HA-free**.
3. `custom_components/fishing/www/fishing-card.js` — one self-contained Lovelace card (no Lit, no npm, no build step).

---

## 2. Non-negotiable constraints

| Rule | Why |
|---|---|
| `model/` imports **stdlib only** (no `homeassistant`, no `aiohttp`, no `numpy`, no `astral`) | the model is testable offline, runnable in `scripts/demo.py`, and cannot be corrupted by HA |
| Tests run with **`python -m unittest`**, stdlib only, **no network**, **no third-party imports** | the user's system Python has no pip and **no tz database** (see §7.1) |
| `astral` + `numpy` live only in `scratch/venv/` and `scripts/regen_*.py` | they are reference/validation tools, never runtime deps |
| Reference values are committed as **JSON fixtures** in `tests/fixtures/` and regenerated by dev-only scripts | tests stay offline and deterministic |
| One HA config entry = one fishing spot = one device | multi-spot support is a first-class requirement |
| Missing data ⇒ drop the factor, renormalise the remaining weights, lower `confidence`, say so in `notes` | never invent a score |
| Light/timing must be computed from **sun altitude**, not clock hour | a clock-hour curve is wrong in the tropics *and* at 64°N |
| Card: single file, no framework, no build step | user installs by dropping one file in `www/` |

## 6. Conventions that must not drift

* **`Sample = (datetime, float)`**, always in the **spot's local wall clock**. Datetimes must be
  **consistently naive or consistently aware within one evaluation**. Landmine: astronomy returns
  **aware UTC** datetimes even for naive input, so `ctx.astronomy_for()` events and a naive series
  cannot be compared directly. `scoring.py` must normalise (see §7.3).
* Units: °C, m/s, hPa, mm, W/m², degrees, hours, J/kg; 0–100 for cloud/humidity percentages,
  0–1 for indices. Curve `kind` documents the x-axis: `anomaly_sigma | physical | index01 | hours`.
* Scores are **−1..+1** inside the model, mapped to 0–10 only at the UI boundary.
* Any factor that cannot be computed returns `None`, and `weighted_score` renormalises and reports
  the dropped names — that becomes the `confidence` attribute and the card's "not enough data" note.
* Anomaly space (sigma vs local normal) is what makes "1.5σ warmer than normal for June" comparable
  between a Scottish sea loch and an Alpine lake. Prefer anomaly over raw units for cross-site work.
* Docstrings in this codebase explain **why** in plain language (often with the angling observation
  that motivated the term). Keep that voice — it is deliberate, it is what makes the model reviewable.

## 7. Gotchas already paid for (do not re-pay)

### 7.1 No tz database offline
`ZoneInfo` fails for every IANA key in the system Python. Tests rebuild fixed offsets from fixture
`utc_offset_min` (`timezone(timedelta(minutes=...))`). **Recommended addition to `SpotContext`:**
a `tz_offset_min: int | None = None` field used by `.tz` when set, so a spot can be tested at a
real local offset without a tz db. (`tests/test_astronomy.py` already demonstrates the pattern;
`scripts/regen_event_fixtures.py` is the only dev script allowed to use `ZoneInfo`.)

### 7.2 `astral` is right at mid-latitudes, unreliable at polar ones
Mid-latitude agreement (keep as regression bounds): Enkhuizen sunrise/sunset/noon worst ≈ 24/20/2 s;
Auckland/NYC/Sydney/Singapore ≤ ~18 s; moonrise/set ≤ 1.3–2.3 min. Polar sites: **do not assert
cross-agreement** — astral's own Reykjavik fixture can report a sunset *earlier than* the sunrise
for the same date. Polar behaviour is asserted instead by (a) altitude identity at reported events
(≤ 0.02–0.03°), (b) `polar_day`/`polar_night` flags, (c) night-window ordering, (d) `dark_hours` sanity.
`astral.sun` in v3.2 has **no `dawn_dusk`**; `astral.moon.phase` (not `moon_phase`);
`moon_position(jd)` returns RA, Dec, and *angular* distance — km ≈ `astral_distance * 6378.137`;
`astral.moon.moonrise/moonset` raise `ValueError` on no-rise/no-set days.

### 7.3 Astronomy event selection semantics (already implemented, understand before touching)
* `body_events()` picks the **first event inside the local calendar day** (almanac semantics).
* `day_light()` picks the crossings that **bracket local solar noon** (`_jd_bracketing`) so that
  `sunrise ≤ solar_noon ≤ sunset` and day length stays positive at 64°N where the Sun can set at
  00:02. Do not "simplify" this back to first-in-day.
* `night_windows()` exists because a per-day object cannot express a night that wraps past
  midnight (May at 52°N: civil dusk on the 7th, nautical dusk on the 8th). Use it for "tonight".
* `_crossings(..., near=0.4)` recursively re-scans intervals that stay near the horizon, catching
  short polar grazing events a fixed step misses.

### 7.4 Lunar ephemeris is **fitted**, not transcribed
`LUNAR_LON_TERMS / LUNAR_LAT_TERMS / LUNAR_RAD_TERMS` (20/10/12 terms) were derived by orthogonal
matching pursuit against full `astral` theory over 1950–2100 (`scripts/regen_lunar_series.py`).
Residuals vs full theory: lon rms 0.68′ max 3.1′; lat rms 0.54′ max 2.1′; radius rms 60 km max 232 km.
Shipped-vs-fixture error: rms 0.97′, max 2.20′. **Never hand-edit these coefficients** — re-derive.
Short baselines are ill-conditioned (near-commensurable constituent frequencies); keep the
1950–2100 baseline and canonical (D, M_sun, M_moon, F) half-space.

### 7.5 Open-Meteo quirks (probed; endpoints confirmed)
| Endpoint | Notes |
|---|---|
| `https://api.open-meteo.com/v1/forecast` | main; cloud variables are **`cloud_cover_low` / `_mid` / `_high`** (not `low_cloud_cover`) |
| `https://marine-api.open-meteo.com/v1/marine` | **must** be this host; sea/wave variables on the forecast host are rejected. `sea_surface_height` was **not accepted** in the request tried. Inland coordinates return **`null`** SST — expect it and fall back to the water model |
| `https://flood-api.open-meteo.com/v1/flood` | river discharge works; daily resolution, and only where a gauge model cell exists |
| `https://air-quality-api.open-meteo.com/v1/air-quality` | works; optional, off by default |
| `https://geocoding-api.open-meteo.com/v1/search` | for setup-time place search |
| hydrology endpoint | returned empty/invalid in tests — **do not depend on it** |
Also: marine and flood hosts reject non-coastline/unsupported cells with `null` fields rather than
errors. Parse defensively: check `daily/hourly` keys exist and each array is non-empty.

### 7.6 Pressure subtlety
Station pressure ≠ MSLP. Keep **station pressure** as the primary series for local tendency/anomaly
when the user has a real barometer (`pressure_source='station'`), reduce MSLP to station elevation
only for display (`pressure.sea_level_to_station_local`), and use `pressure.sensor_offset()` to
calibrate a local sensor against model MSLP. A wrong mean-air temperature injects ≈1 hPa per 30 m
of elevation error. `PRESSURE_TENDENCY_3H` must be evaluated on the **diurnal-tide-corrected**
tendency, or the solar semi-diurnal tide manufactures fake "falling barometer" signals
(`pressure.analyse(..., diurnal_cycle=pressure.build_diurnal_cycle(hourly))`).

### 7.7 Bugs the Phase 2 tests found (all fixed, all regression-tested)
* `series.resample` looped forever on a real gap (cursor advanced, index did not).
* `species.profile("European_bass")` silently returned `mixed_general` (lowercased key vs mixed-case id).
* `pressure.analyse` subtracted the diurnal tide over the *next* 3 h while the raw tendency looks *back*
  3 h, doubling the artefact; fixed to `cycle_tendency(cycle, (hour-3) % 24, 3)` (also 6 h and `_front`).
* `pressure` front discount ignored *measured-flat* wind/cloud/temperature (0.0 was read as "no data").
* `water_temp.model_series` fed percent cloud/humidity into functions that clamp to 0-1.
* `solunar.windows` lunar-clock fallback put minors at +/-1/2 lunar day (= the other major); now +/-1/4
  from the transit, and only for the events actually missing.
* `hydro` level trend was always `None` for a daily gauge (24 h window < 3 samples) and used a raw-Q
  slope over a log-space sd; now `level_slope_per_day` on log(Q+1) with a 72 h fallback. Daily rain is
  no longer read as an mm/h intensity.
* `context.astronomy_for` anchored a naive `when` on UTC midnight; it now always uses the spot's local
  midnight (aware), so moonrise/moonset fall in the right local day.
* `series.at/extrema/mean/sum_over` were O(N) per call (model_series O(N^2)); now bisect-based. They
  therefore assume a **sorted** series (use `clean`).
* `pressure._temp_jump` (front corroboration, and the `cold_snap`/`cold_front` advice) compared air now
  with 6 h ago, i.e. about -5 degC every evening: a "cold front" twice a day. It now subtracts the same
  window one day earlier (second difference) and is None when that day is missing.
Still open: `solunar.intensity_at` / `windows` return aware-UTC datetimes and raise `TypeError` for a
naive `when`; `scoring.py` must normalise (see §6).

#### 8.2.1 As built: where `scoring.py` differs from the spec above (trust this, not the sketch)
* **Time contract.** `evaluate/prepare/hourly_curve` take a naive *local* `when` (aware is converted via
  `ctx.tz`). Astronomy always gets an aware `when`. `scoring.local_event(ctx, dt)` converts astronomy
  events for comparison with series times. `Evaluation.light` is the aware `DayLight`.
* **`prepare(ctx, when, now=None)`** computes everything species-independent once (`Prepared`); pass it to
  `evaluate(ctx, when, prof, prepared)` to score 22 species cheaply. A `Prepared` for a different instant is
  ignored, never reused. `now` is the instant live sensor readings refer to (the curve start).
* **Not-applicable factors are removed from the weights, not treated as missing**: `uv` at night,
  `moonlight` by day, `tide` on non-tidal water. They appear in `Evaluation.not_applicable` and never
  lower `coverage`/`confidence`. Unavailable factors stay in `factors` with `source='unavailable'`, weight 0.
* **Water temperature:** a measured `water_temp` series wins; else a probe (`ctx.water_sensor`) or SST sets
  the level by shifting the *model* series by a constant offset at `now` (so a sensor-vs-model gap is not
  read as a thermal shock); else the model alone. The model series is memoised in `ctx.memo` (cleared by
  `ctx.invalidate()`).
* **`front`:** steady pressure scores as "no front" (`FRONT_INDEX(0)`, slightly negative); it is only
  *unavailable* when there is no pressure data at all.
* **`precip`:** `RAIN_ON_DAYS` takes the raw 72 h total in mm (the curve's x-axis), not `rain_72/24`.
* **`solunar`:** the tide bonus is added only for tidal spots, scaled by the window intensity.
* **Confidence/coverage:** a factor built from partial inputs counts partially: `HydroState.completeness`
  (a river judged from rain alone is ~0.4) reduces coverage, so losing the gauge lowers confidence.
* `Evaluation` also carries `season_factor`, `not_applicable`, and the `water`/`pressure`/`hydro` analyses
  and raw `obs` for `advice.py` to classify tactic states from.
* `tests/support.spot_context()` builds a deterministic synthetic spot (neutral calm June baseline on a
  Dutch lake); perturb exactly one input per test. `scripts/demo.py` should reuse it.

## 10. Things not to do
* No `numpy`, `pandas`, `astral`, `scipy`, `lit` at runtime. Ever.
* No hand-editing of the lunar coefficient tables.
* No clock-hour-based light curves — sun altitude only.
* No asserting polar-site agreement with `astral`.
* No `ZoneInfo` in `model/` without a `timezone.utc` fallback; no tz-dependent tests.
* No interpolating across large sensor gaps in `series.at` — bounded nearest-sample, or it lies.
* No "solunar is mysticism" rewrites either: keep the windows as a *timing prior with a labelled
  mechanism* (transit/anti-transit and rise/set geometry + lunar clock), never as a standalone
  confidence claim. The `moonlight_effect`/`light_window` split is what does the real work.
